# 로또

## 과제 개요

해당 과제는 6자리의 로또 번호와 사용자가 입력한 6자리의 숫자와 1자리의 보너스 숫자로 결과를 구하는 로또 게임을 구현하는 과제이다.<br>
해당 과제의 주요 구현 목표는 클래스를 통해 로또 관련 필드를 정의하고 생성된 객체들을 통해 하나의 큰 기능을 수행하도록 구현하는 것이다.<br>
추가적으로 로또 클래스의 각 기능을 구현하면서 함수에 대한 단위 테스트 함수로 구현한 기능을 검증하는 영역을 확보해야 한다.

## 기능 흐름 정리

1. 로또 구입 금액을 입력한다.(로또 한장당 가격은 1000원)
2. 구입 금액에 따른 로또 개수를 구한다.
3. 로또의 개수만큼 사용자의 추첨 번호를 생성한다.(쉼표 기준 6자리의 중복이 없는 1~45 숫자)
4. 사용자의 추첨 번호를 입력받는다. ( 기준 동일 )
5. 사용자의 보너스 추첨 번호를 입력한다. (추첨 번호와 중복되지 않는 1개의 숫자)
6. 생성된 로또번호와 사용자의 번호를 비교해서 각 로또의 결과를 도출하고 결과 통계를 낸다.
    - 1등: 6개 번호 일치 / 2,000,000,000원
    - 2등: 5개 번호 + 보너스 번호 일치 / 30,000,000원
    - 3등: 5개 번호 일치 / 1,500,000원
    - 4등: 4개 번호 일치 / 50,000원
    - 5등: 3개 번호 일치 / 5,000원
7. 당첨 등수에 따라서 몇개가 당첨됐는지 출력한다.
8. 구입 금액과 당첨 금액의 비율을 통해 수익률을 출력한다.

## 기능 요구사항 체크리스트

입력

-   [x] `구입금액을 입력해 주세요.` 출력과 함께 사용자가 로또 구입 금액을 입력한다.
-   [x] `당첨 번호를 입력해 주세요.` 출력과 함께 사용자가 추첨 번호를 입력한다.
-   [x] `보너스 번호를 입력해 주세요.` 출력과 함께 사용자가 보너스 추첨 번호를 입력한다.

입력 처리

-   [ ] 입력된 로또 구입 금액을 숫자로 바꾸어 `1000원` 단위로 나누어 구입 로또 개수를 구한다.
-   [ ] 사용자 추첨 번호를 `,` 쉼표를 기준으로 구분하여 숫자로 저장한다.
-   [ ] 보너스 번호를 숫자로 변환한다.

로또 게임

-   [x] 로또 번호 생성 : 6자리의 중복이 없는 1에서 45 사이의 난수를 생성한다.
-   [x] 구입 로또 생성 : 구입 개수만큼 ‘로또 번호 생성’ 한다.

-   [ ] 로또 당첨 확인 : 추첨번호와 로또를 비교하여, 일치하는 번호의 개수를 구한다.
-   [ ] 보너스 번호 확인 : 로또에 보너스 번호가 있는지 확인한다.
-   [ ] 당첨 등수 확인 : 추첨 번호 일치 개수와 보너스 번호 일치 여부를 통해 당첨 등수를 구한다.
-   [ ] 구입 로또 결과 확인 : 구입한 로또들의 ‘로또 당첨 확인’ 과 ‘보너스 번호 확인’으로 각 로또들의 ‘당첨 등수 확인’한 결과를 도출한다.
-   [ ] 로또 수익률 계산 : 각 로또의 당첨 등수에 따른 상금을 모두 합하여 구입금액과 비교한 수익률을 구한다.(소수점 둘째 자리에서 반올림)

출력

-   [ ] 사용자가 구입한 로또의 개수를 `[개수]개를 구매했습니다.` 로 출력한다.
-   [ ] 사용자가 구입한 모든 로또의 결과를 `[a, b, c, d, e, f]` 와 같은 형식으로 한줄씩 출력한다.
-   [ ] 당첨 통계 추출의 헤더를 `당첨 통계\n---` 와 같은 형식으로 출력한다.
-   [ ] 사용자가 구입한 로또의 결과에 따른 각 당첨 등수를 각 등수의 형식에 따라 출력한다.
    -   `3개 일치 (5,000원) - n개`
    -   `4개 일치 (50,000원) - n개`
    -   `5개 일치 (1,500,000원) - n개`
    -   `5개 일치, 보너스 볼 일치 (30,000,000원) - n개`
    -   `6개 일치 (2,000,000,000원) - n개`
-   [ ] 총 수익률을 `총 수익률은 nn.n%입니다.` 와 같은 형식으로 출력한다.

## 예외 사항 체크리스트

### 📌 입력 조건 검증

구입 금액

-   [ ] 입력이 없을 경우
-   [ ] 숫자가 아닐 경우
-   [ ] 1000 단위로 나누어 떨어지지 않는경우

당첨 번호

-   [ ] 입력이 없을 경우
-   [ ] 쉼표 `,`와 숫자 외의 문자가 있을 경우

보너스 번호

-   [ ] 입력이 없을 경우
-   [ ] 숫자가 아닐 경우

### 📌 입력 조건 검증

당첨 번호

-   [ ] 6개가 아닐 경우
-   [ ] 각 숫자가 1에서 45사이의 숫자가 아닐 경우
-   [ ] 중복된 숫자가 있을 경우

보너스 번호

-   [ ] 1에서 45사이의 숫자가 아닐 경우
-   [ ] 당첨 번호와 중복된 숫자일 경우

## 구현과정

TDD(Test Driven Development) 개발 방법론을 적용해봤다.<br>
TDD 개발 방법론이란 기능 단위 테스트를 작성하고 테스트에 대한 코드를 작성한 뒤 코드를 개선하며 단위테스트를 반복하는 개발 방법론이다.<br>
TDD의 장점으로는<br>

1. 디버깅이 간편해짐 : 기능별로 단위 테스트를 미리 작성하고 자동화된 테스트를 진행하여 어느 기능에서 장애가 발생했는지 빠르게 인지할 수 있다.
2. 재설계의 시간을 단축 : 코드를 작성하기 전 미리 단위 테스트를 생각해보기 때문에 다양한 예외 사항에 대해 생각해볼 수 있다.
